Servicio predictivo de inventario con MongoDB

Este informe explica, de forma sencilla, cómo se integra el nuevo microservicio predictivo con FarmaExpres, cómo toma datos del sistema relacional, cómo los prepara en MongoDB y cómo calcula una predicción básica de demanda.

La solución no reemplaza el backend principal. Funciona como un microservicio aparte, conectado por el API Gateway, para apoyar decisiones de reposición de medicamentos.

Qué se construyó

Microservicio Python

API con FastAPI encargada de recibir datos, limpiarlos, recalcular el modelo y exponer predicciones.

MongoDB

Base no relacional para guardar datos crudos, datos limpios, predicciones, métricas y snapshot de productos.

Integración FarmaExpres

El API Gateway enruta /api/predictions hacia el microservicio y conserva el uso de JWT.

Flujo de integración

El proceso comienza en el frontend o en una petición REST. El gateway valida la ruta, el microservicio predictivo solicita un snapshot analítico al servicio de inventario y luego guarda una copia procesable en MongoDB.

1

Usuario o frontend

Solicita estado, ingesta, limpieza, entrenamiento o consulta de predicciones.

2

API Gateway

Recibe /api/predictions, aplica seguridad y envía la petición al servicio predictivo.

3

Prediction Service

Usa el token JWT para pedir datos al inventory-service.

4

Inventory Service

Construye un snapshot con productos activos, lotes y movimientos de inventario.

5

PostgreSQL

La información viene de las tablas relacionales gobernadas por el backend y Liquibase.

6

MongoDB

Guarda raw_data y products_snapshot como base flexible para análisis.

7

Limpieza

Normaliza nombres, fechas, cantidades, duplicados y registros incompletos.

8

Predicción

Calcula demanda esperada, riesgo de agotamiento y prioridad de reposición.

Datos usados para el modelo

Dato Origen Uso en la predicción
Medicamentos activos inventory-service / productos Define qué productos se evalúan y evita analizar productos inactivos.
Movimientos tipo salida Historial de inventario Se usan como señal de demanda histórica.
Stock actual y stock mínimo Producto y movimiento Permite estimar si la demanda proyectada supera la disponibilidad.
Lotes y vencimientos Inventario por lote Ayuda a conservar contexto para análisis posterior de rotación y vencimiento.

Los datos de prueba existen para validar el flujo local. No se presentan como datos reales de producción.

Tratamiento de datos

Limpieza aplicada

  • Elimina duplicados por producto, tipo de movimiento, fecha, cantidad y lote.
  • Valida campos vacíos o incompletos.
  • Normaliza nombres de medicamentos, quitando tildes y espacios repetidos.
  • Convierte fechas a formato ISO para compararlas con consistencia.
  • Marca cantidades negativas, stock negativo o fechas inválidas.

Colecciones MongoDB

  • raw_data: entrada original desde inventario o datos de prueba.
  • cleaned_data: registros normalizados y validados.
  • predictions: resultado del modelo predictivo.
  • model_metrics: métricas de limpieza y entrenamiento.
  • products_snapshot: copia del estado relevante de medicamentos.

Modelo predictivo

La primera versión usa un promedio móvil de 30 días. Es una técnica estadística sencilla y explicable: suma las salidas recientes de cada medicamento, calcula un promedio diario y lo multiplica por el horizonte de predicción. Por defecto, el horizonte es de 7 días.

Demanda esperada

promedio_diario × días. El resultado se redondea hacia arriba para no subestimar unidades.

Días a agotamiento

stock_actual / promedio_diario. Si no hay demanda reciente, queda sin estimación.

Riesgo

Sin stock, alto, medio o bajo, según stock actual, stock mínimo y demanda esperada.

Este modelo es adecuado para una primera entrega porque se puede explicar, probar y ajustar con datos reales antes de pasar a algoritmos más avanzados.

Cómo se ejecuta localmente

  • Backend principal: docker compose --env-file .env.dev up -d --build.
  • Microservicio NoSQL: docker compose --env-file .env.dev up -d --build.
  • Frontend: se entra con un usuario válido y se abre la opción Predicciones.
  • El frontend llama al gateway, no directamente a MongoDB.

Para QA o main se cambian los archivos de entorno y la red Docker, siguiendo el mismo estilo usado por FarmaExpres.
